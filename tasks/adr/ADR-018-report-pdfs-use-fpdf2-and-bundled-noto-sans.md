# ADR-018 — Report PDFs use fpdf2 and bundled Noto Sans

- Status: Accepted (C08 complete)
- Date: 2026-08-26
- Decision makers: Product/Engineering team
- Relates to: C08 in [SPEC-architecture-improvement-program](../specs/SPEC-architecture-improvement-program.md)

## Context

The report API already exposed `GET /api/v1/reports/{filename}/pdf` behind a
`ReportPdfRenderer` domain port, but production composed no implementation. The route therefore
returned `501 pdf_export_unavailable` for every stored report. Shipping the renderer required a
deliberate dependency and font decision because Vietnamese output must be deterministic on
Windows, Linux, offline CI, and packaged installations.

The accepted contract also required a narrow Markdown surface, extractable Unicode text, and a
typed composition cutover rather than another optional `app.state` slot.

## Decision

**Report PDF export uses fpdf2 with repository-bundled Noto Sans.**

1. `Fpdf2ReportPdfRenderer` implements the existing domain port in
   `integrations/report_pdf`; the domain remains unaware of fpdf2.
2. Production constructs the adapter once and stores it in
   `CoworkRuntime.report_pdf_renderer`. The report route reads only that typed field.
3. Four static Noto Sans instances (regular, bold, italic, and bold italic) are bundled as package
   data under the SIL Open Font License. They are derived from the official `google/fonts`
   variable fonts at a recorded commit and checksum. Runtime rendering performs no network or
   host-font discovery.
4. The adapter escapes raw HTML before translating only the supported Markdown subset: headings,
   paragraphs, ordered and unordered lists, emphasis, links rendered as visible label plus URL,
   inline code, and fenced code. Unsupported constructs remain readable literal text.
5. `pypdf` is a development-only dependency used to reopen generated bytes and prove that
   representative Vietnamese text is extractable. A `%PDF` prefix alone is not acceptance.
6. The existing transport contract remains: missing reports are `404`; successful responses are
   `application/pdf` attachments named from `ReportFilename`. An optional `None` renderer remains
   valid only for narrow injected test runtimes, where the existing `501` response is preserved.

## Rationale

- **Portable installation.** fpdf2 is pure-Python-friendly on Windows and does not add the native
  Pango/MSYS2 runtime required by WeasyPrint.
- **Adequate fidelity.** Its HTML writer covers the deliberately small report Markdown contract
  without introducing a general HTML/CSS rendering surface.
- **Deterministic Unicode.** Bundling Noto Sans makes Vietnamese glyph coverage independent of the
  host operating system and allows font subsetting in the emitted PDF.
- **Request-path cost.** Static font instances move variable-font interpolation out of the request
  path. On the implementation workstation this reduced the representative render from about
  5.7 seconds to under 0.1 seconds.
- **Trust boundary.** Escaping source HTML before admitting known tags prevents model-authored
  report text from becoming arbitrary renderer markup.

## Alternatives considered

### WeasyPrint with bundled Noto Sans

Rejected for this surface. It offers stronger CSS fidelity but adds a native rendering runtime on
Windows that is disproportionate to headings, lists, emphasis, links, and code blocks.

### ReportLab with bundled Noto Sans

Rejected. It is mature and portable, but its Platypus mapping is more manual for the same accepted
Markdown subset and the project has no existing ReportLab standard to justify that cost.

### Host-installed fonts

Rejected. Output and glyph coverage would vary by machine, and offline packaged deployments could
silently lose Vietnamese text.

### Bundle variable fonts and instantiate them per request

Rejected after measurement. It was functionally correct but added roughly 5.7 seconds to each
small PDF render on the implementation workstation.

## Consequences

- `fpdf2>=2.8,<3` is a runtime dependency; `pypdf>=6,<7` is a development dependency.
- The installed wheel includes the four font files, license, and provenance record, increasing
  package size in exchange for deterministic offline rendering.
- Links are intentionally readable text (`label (URL)`), not active PDF hyperlinks.
- Extending the Markdown contract requires tests at the renderer boundary; it must not be achieved
  by passing untrusted raw HTML through to fpdf2.
- C08 is complete, and C10's `report_pdf_renderer` untyped survivor is deleted. The two remaining
  `app.state` exceptions are the request-time chat controller cache and its factory.
